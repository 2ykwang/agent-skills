# decision-board

같은 형태의 선택지가 여러 개 쌓였을 때, 하나의 HTML 보드에 미리보기와 함께 나란히 띄웁니다. 채팅을 위아래로 훑는 대신 한자리에서 전부 고를 수 있습니다. 고른 결과는 에이전트가 바로 적용할 수 있는 JSON으로 돌아옵니다.

## 언제 사용하나요

- 여러 개 중 하나를 고르는 결정이 여러 건이고, 선택지 구성이 서로 비슷할 때(레이블, 비용, 미리보기)
- 각 선택지의 미리보기를 나란히 놓고 봐야 판단이 설 때. 한 문장 설명으로 충분하다면 그냥 물어보는 편이 빠릅니다
- 한 사람이 한자리에서 결정할 때. 여러 사람이 시차를 두고 검토하는 상황에는 맞지 않습니다

## 사용법

```
/decision-board
```

보통은 같은 형태의 선택지가 쌓이면 에이전트가 알아서 이 스킬을 꺼냅니다. 어느 쪽이든 에이전트가 결정 항목을 먼저 뽑아내고, 초안을 보여주며 확인을 받은 뒤 `http://localhost:7117`에 보드를 엽니다. 그다음은 이렇게 진행됩니다.

1. 결정을 하나씩 훑어봅니다. 모든 선택지의 미리보기가 보이므로 고르기 전에 근거를 읽을 수 있습니다.
2. 결정마다 하나씩 고릅니다. 나중에 다시 볼 항목은 `hold`로 표시해둘 수 있습니다.
3. Submit을 누릅니다. 중단하려면 Cancel이나 ESC를 누르면 됩니다.

이후 에이전트가 선택을 읽어 실제 작업으로 옮깁니다(PR 생성, 문서 수정 등). 취소하면 결과 파일이 만들어지지 않습니다. 이때 에이전트는 추천 선택지로 대신 채우지 않고, 어떻게 할지 다시 묻습니다.

결정이 15개를 넘어가면 보드에 카테고리 필터가 생깁니다.

## 필요한 것

- `python3` (표준 라이브러리만 씁니다)

## 알아두면 좋은 점

- 선택은 브라우저에 자동 저장됩니다. 새로고침해도 작업이 날아가지 않습니다. 다만 결정을 추가하거나 지우거나 이름을 바꾸면 저장된 상태를 일부러 초기화합니다.
- 포트는 바꿀 수 있고, 보드를 독립 HTML 파일로 내보내 오프라인에서 공유할 수도 있습니다. 이 사본에는 Submit 버튼이 없습니다.
- 스킬 자체는 저장소를 수정하지 않습니다. 선택을 읽고 실제로 반영하는 일은 에이전트가 합니다.
- 결정 하나당 하나만 고릅니다. 다중 선택이나 가중치, 결정 사이의 의존 관계, 여러 사람의 검토는 지원하지 않습니다.
