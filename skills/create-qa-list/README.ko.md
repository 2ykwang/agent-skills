# create-qa-list

코드나 스펙, PR, 또는 지금 나눈 대화를 QA 테스트 케이스 목록으로 바꿔줍니다. 개발자가 아닌 사람이 읽고 그대로 따라 할 수 있는 형태이고, CSV나 HTML 리포트로 내보냅니다.

## 설치

### Claude Code

```bash
claude plugin marketplace add 2ykwang/agent-skills
claude plugin install create-qa-list@2ykwang-agent-skills
```

### npx skills

```bash
npx skills add 2ykwang/agent-skills --skill create-qa-list
```

## 언제 사용하나요

- 개발자가 아닌 사람도 실행할 수 있는 QA 테스트 케이스나 테스트 계획, 체크리스트가 필요할 때
- 테스트 도구에 넣을 CSV, 또는 공유할 HTML 리포트로 케이스를 정리하고 싶을 때
- 방금 만들었거나 여기서 이야기한 기능이 대상일 때. 대화 내용 자체가 입력이 됩니다

## 사용법

```
# 지금 나눈 대화를 바탕으로
/create-qa-list

# PR이나 파일, 스펙을 지정해서
/create-qa-list https://github.com/org/repo/pull/42
```

한 번에 다 쏟아내지 않고 단계를 밟습니다. 전체 행을 채우기 전에 범위와 카테고리, 케이스 목록을 먼저 확인받습니다. 30행짜리 목록이 잘못된 가정 위에 세워지는 일을 막기 위해서입니다.

## 동작 방식

1. **범위 정하기.** 어떤 기능이 대상인지 파악하고, 무엇이 포함되고 무엇이 빠지는지, 어떤 플랫폼과 역할을 기준으로 볼지 확인합니다.
2. **카테고리와 우선순위 합의.** 케이스를 어떻게 묶을지, 어떤 기준으로 P1부터 P3까지 매길지 먼저 맞춥니다.
3. **케이스 목록 초안.** 한 줄짜리 제목만 먼저 보여줍니다. 빠진 케이스를 잡아내기에 가장 저렴한 시점입니다.
4. **내보낼 형식 선택.** CSV, HTML, 또는 둘 다.
5. **작성과 검증.** 확정된 목록을 전체 행으로 채우고 번들 스크립트로 파일을 만든 뒤, 결과물을 다시 읽습니다. 모든 기대 결과가 실제 동작에 근거하는지, 코드 심볼이 셀에 새어 나가지 않았는지, 행마다 컬럼이 같은지, 우선순위가 합의한 기준을 따르는지 확인합니다.

## 결과물

기본 컬럼은 일곱 개입니다. `TC_ID`, `Category`, `Scenario`, `Preconditions`, `Steps`, `Expected Result`, `Priority`. 사용자가 무엇을 하고 무엇을 보게 되는지, 즉 동작과 상황으로만 씁니다. 함수 이름이나 파일 경로 같은 코드 용어는 넣지 않습니다. 파일은 지정한 출력 디렉터리에 저장됩니다(기본값은 `qa_output/`).

- **CSV.** 테스트 관리 도구나 스프레드시트로 가져갈 때 씁니다.
- **HTML.** "Download CSV" 버튼이 붙어 있어, 읽기도 공유하기도 편한 리포트입니다.

## 필요한 것

- `python3` (표준 라이브러리만 씁니다)

## 알아두면 좋은 점

- 모든 케이스는 확인된 동작에 근거합니다. 확인되지 않은 것은 추측해서 채우지 않고 needs-confirmation으로 표시합니다.
- 자동화 테스트 코드(pytest, jest)를 작성하거나 실행하는 용도, 코드 리뷰, 테스트 전략 문서에는 맞지 않습니다.
