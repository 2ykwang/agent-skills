# instruction-eval

에이전트가 놓인 조건 하나(지침, 참조 문서, 훅, 권한)를 바꾼 뒤, 같은 프롬프트를 변경 전후에서 여러 번 돌려 결과가 실제로 어떻게 달라지는지 보여줍니다. 두 조건의 답변을 나란히 놓은 HTML 리포트를 만듭니다.

Claude Code 기반입니다. 두 조건 모두 `claude -p` 서브프로세스로 실행됩니다.

## 설치

### Claude Code

```bash
claude plugin marketplace add 2ykwang/agent-skills
claude plugin install instruction-eval@2ykwang-agent-skills
```

### npx skills

```bash
npx skills add 2ykwang/agent-skills --skill instruction-eval
```

## 언제 사용하나요

- **규칙을 추가할지 정해야 하는데, 효과가 있다는 근거가 필요할 때**
  - `/instruction-eval CLAUDE.md에 "주석은 자기완결적으로 쓴다" 규칙을 추가했는데, 이게 있을 때랑 없을 때 결과가 실제로 달라지는지 봐줘`
- **기존 규칙을 지우고 싶지만 지워도 된다는 근거가 없을 때**
  - `/instruction-eval CLAUDE.md의 "코드 수정 전에 관련 파일을 전부 읽어라" 규칙을 빼고 돌려서, 빼면 실제로 문제가 생기는지 확인해줘`
- **같은 규칙을 두 가지 문구로 써놨는데 어느 쪽이 더 잘 먹히는지 모를 때**
  - `/instruction-eval "답변은 간결하게" 와 "결론부터 쓰고 근거는 세 줄 이내로" 중 어느 문구가 더 잘 지켜지는지 비교해줘`
- **참조 문서를 놓아뒀는데 에이전트가 실제로 읽고 있는지 모를 때**
  - `/instruction-eval docs/api-conventions.md 를 놓아뒀는데 에이전트가 이걸 실제로 찾아 읽고 인용하는지, 지웠을 때랑 비교해줘`

애플리케이션 코드 변경이나 자동화 테스트로 이미 검증되는 것에는 쓰지 않습니다.

## 사용법

```
/instruction-eval <무엇과 무엇을 비교할지>
```

비교 축만 알려주면 조건 두 개를 만들고, 프롬프트 세트와 실행 횟수까지 짜서 실행 전에 승인을 받습니다.

## 동작 방식

1. **조건 설계.** 축(한쪽에는 있고 다른 쪽에는 없는 것)을 정하고 작업 디렉터리 두 개를 만든 뒤, `diff -rq`로 축 말고 다른 게 다르지 않은지 확인합니다.
2. **승인.** 축, `diff -rq` 출력, 프롬프트 전문, n, 모델을 그대로 보여줍니다. 승인 없이는 실행하지 않습니다.
3. **실행.** `run_ab.py`가 두 디렉터리에서 `claude -p`를 프롬프트당 n회씩 돌립니다. 병렬로 돌려 한쪽이 프롬프트 캐시 이득을 보지 않게 합니다.
4. **리포트.** `render_report.py`가 단일 파일 HTML을 만듭니다. 두 답변을 나란히 놓고, 실행 시간·턴 수·출력 토큰의 중앙값과 실측 범위를 함께 보여줍니다.
5. **해석.** 답변을 읽고 `insights.json`을 작성하면 리포트에 합쳐지며, 측정된 데이터와 시각적으로 구분되어 표시됩니다.

리포트가 쓰는 지표는 셋뿐입니다. 입력 토큰과 비용은 프롬프트 캐시에 지배되어 작업량과 반대로 움직일 수 있어 제외했습니다. 두 조건의 실측 범위가 겹치는 행에는 표시가 붙습니다. 그 델타는 조건의 효과가 아니라 실행 편차일 수 있습니다.

## 필요한 것

- Claude Code CLI (`claude -p`를 서브프로세스로 실행)
- `python3`
