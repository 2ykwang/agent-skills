# code-review-report

코드 변경을 HTML 리포트 한 장으로 정리합니다. diff와 함께, diff에는 남지 않는 맥락까지 담습니다. 왜 그렇게 고쳤는지, 어떤 대안을 검토하다 접었는지, 무엇을 감수했는지, 무엇이 아직 남았는지. 여기에 우선순위를 매긴 리뷰 포인트가 더해집니다.

## 언제 사용하나요

- 규모 있는 변경이나 리팩터링, 기능 작업을 마치고 리뷰를 준비할 때
- 리뷰어에게 diff만이 아니라 그렇게 판단한 근거까지 보여주고 싶을 때
- 변경 내용을 공유할 수 있는 HTML 한 장으로 정리해야 할 때

## 사용법

```
/code-review-report
```

작업을 진행한 그 대화에서 실행하는 편이 좋습니다. "왜"에 해당하는 이야기가 거기 쌓여 있기 때문입니다. 기본 범위는 현재 브랜치와 기본 브랜치의 차이에 커밋하지 않은 작업까지 더한 것입니다.

## 동작 방식

1. 변경을 모읍니다. 커밋된 diff, 아직 커밋하지 않은 작업, git이 추적하지 않는 새 파일까지 챙깁니다.
2. diff에 남지 않는 맥락을 모읍니다. 설계 결정, 접어둔 대안, 감수한 트레이드오프, 아직 끝내지 못한 부분입니다.
3. 우선순위를 매긴 리뷰 포인트(P1부터 P3까지)를 뽑습니다. 서브에이전트가 그 맥락을 함께 받아 코드를 보며, 정확성이나 보안, 마이그레이션 호환성 같은 관점마다 하나씩 붙습니다. 변경이 크면 병렬로 돌립니다.
4. 리포트를 HTML 한 파일로 쓰고 브라우저로 엽니다.

## 결과물

프로젝트 루트에 HTML 파일 하나가 생깁니다(`<작업명>-review-report.html`). 문법 강조가 들어간 diff, 각 변경의 배경, P1부터 P3까지의 리뷰 체크리스트가 담기고, 각 변경과 해당 리뷰 포인트는 서로 링크로 오갑니다. highlight.js를 파일 안에 넣어두기 때문에 네트워크가 없어도 열립니다.

리포트는 여러분이 작업하는 언어로 작성됩니다. 코드만 원문 그대로 둡니다.

## 필요한 것

- `git`
- `python3` (표준 라이브러리만 씁니다)

## 알아두면 좋은 점

- 코드는 읽기만 합니다. 새로 쓰는 건 HTML 리포트 하나뿐입니다.
